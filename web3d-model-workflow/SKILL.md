# 网页三维模型：分件生成与组装

根据用户的设计稿、主体参考和已有工程，交付可继续编辑、可以按部件拆解的模型。只制作当前请求需要的内容；用户要求建模时，不自行发布网站。

## 1. 自动识别本项目输入

先读当前任务上下文和项目目录中的设计图、模型工程、结构资料与已有资产清单。复用用户已确认的版本，不让用户把同一项目中的文件再次上传。多个版本无法从记录判断时，先对照预览及修改记录；仍有实质歧义再问。

## 2. 选择 Blender 控制方式

先读 [连接方式](references/connections.md)，检查真实可用工具，再选择：
- MCP：修改已经打开的场景，分批操作并读取结果。
- 脚本控制：规则结构、重复部件、批量组装、导出与后台渲染。
- 界面操作：用户要看操作过程，或必须使用只有界面入口的功能。

三者是可选择的控制路径，不要求同时安装。没有 Blender 或所需连接时，列明缺项并按已有授权处理；skill 本身不包含 Blender、连接服务或云端额度。可调用的 `blender-control` skill 存在时，可按它的环境检查与执行指引操作。

## 3. 按部件选择建模方式

先形成简洁清单：部件名称、用途、参考来源、是否独立运动、生成或搭建方式、组装关系。

| 部件需求 | 优先考虑 | 判断依据 |
| --- | --- | --- |
| 精确尺寸、规则结构、重复阵列、明确轴位或连接关系 | GPT 控制 Blender | 便于精确对齐、复制和参数调整 |
| 复杂曲面、雕饰、有机形态或丰富表面纹理 | Aholo Lux3D | 以图片或文字生成独立模型及材质，检查实际轮廓和细节 |
| 已有符合要求的模型 | 复用 | 保留来源和可用范围，避免重复生成 |
| 一个主体包含上述多类需求 | 混合方式 | 按独立部件分工，最后由 GPT 在 Blender 中组装 |

建筑需要参考完整外形时，可按 Aholo Lux3D 当前工作流选择建筑壳体生成；需要按层拆分、精准对齐时，按结构选择分件生成或 Blender 搭建。不要仅因是建筑就一律手工搭建，也不要为了使用生成服务把需要分开的部分融合。

拆分以实际展示需求为准，不按每个螺丝或每片叶子无谓细分。相同部件生成一份后复用。有独立编辑需求的部件，分别准备参考图或描述，分别生成；单次生成一个完整物体不保证它自动具有可拆分零件。

## 4. 用 Aholo Lux3D 生成精细部件

使用已安装的 `aholo-lux3d:lux3d` 官方插件，读取其当前 SKILL.md 与对应执行说明。缺少插件时引导到 Codex 插件页搜索 Aholo Lux3D；账号、区域与密钥按插件指引配置，不把密钥写进提示词、模型清单或工程。

为每个待生成部件使用对应的独立参考，保留全景图用于组装关系。根据外形、细节与材质要求选择该插件当前可用的生成方式，不把某一模式描述成永远最好。

生成前按插件规则取得真实报价，沿用当前任务已有有效授权；不因安装 skill 推断费用授权。记录任务编号，后续恢复已有任务，避免重复计费。分别保留原始生成文件、材质和修整版本。

检查正面、侧面、背面和关键接缝。只有局部缺陷时修改或重新生成该部件，不重做整个场景。曲面与材质的实际质量以检查结果为准。

## 5. GPT 控制 Blender 组装

导入可用部件、已有模型及必要的补建结构。统一单位、比例、朝向和材质表现，设置清楚的部件名称、集合与父子关系。把旋转中心放在实际运动或组装位置。

保存每个可拆部件的初始位置、旋转和缩放；另存拆解方向与距离。拆解展示应从原始变换计算偏移，归位恢复原始变换，避免多次操作不断累加误差。生成模型需要重建或补建时，记录实际处理范围。

保持需要独立展示的部件独立，不将它们合并成一个网格。为网页减轻模型负担时，允许合并无需独立运动的小件，记录最终真正能拆解的层级。保留可编辑的 `.blend` 工程，导出带材质和独立节点的 `.glb`，重开检查材质和分件是否保留。

## 6. 记录资产，供网页任务自动读取

在当前项目的合适输出目录保存 `asset-index.json`。记录项目相对路径，不复制本机私密配置。至少包含：
- 主体及已确认的设计图路径；
- Blender 工程与网页用 GLB 路径；
- 每个可拆部件的稳定名称、父节点、初始变换、拆解方向与距离；
- 每个模型的来源类型（生成／Blender 搭建／复用）、原文件、修整版本；
- 已验证项目与仍需修正的问题。

网站制作开始时，先从当前项目读取此清单和对应文件，自动识别模型与分件，不要求用户手动传递已经完成的资产。清单不存在时检查已有工程与文件，补齐真实清单；不凭文件名猜出不存在的内部结构。

保存并检查文件后，简短给出模型、预览与清单路径。只有实际打开、检查过的效果才记为通过。
